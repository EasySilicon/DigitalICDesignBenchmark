# T10 完整 DUT 布局与 −53.41 ns 审计

审计对象是 v93 的完整 16×16 DUT：16 个 4×4 tile 宏、256 个 PE。
该数据是旧 RTL 候选的布局寄生估算，不能称为最新候选的布线结果，也不能作为 PPA 基线。

## 结论

原生工具没有发现 ps/ns、fF/pF、DBU/µm 混用。A/B 数据打包和输入引脚分组正确。
已确认的问题是结果汇集的物理局部性不足，以及修复策略漏掉了结果数据长线。
最差路径还严重超出 Liberty 表征范围，−53.41 ns 的绝对大小不能作为硅上延迟预测。
这并不使该版本合格：setup/hold 和电气条件仍失败。

## 输入怎样排布

每拍 A/B 各传输 1024 bit。A 分成 16 行各 64 bit，B 分成 16 列各 64 bit。
16/8/4-bit 模式下每条 64-bit lane 分别包含 4/8/16 个元素。
A 行 r 做 r 拍波前错位，B 列 c 做 c 拍错位；进入阵列后 A 向右、B 向下逐跳寄存转发。
两侧还存在共同的入口流水延迟。

| 操作数 | 实际物理引脚排列 | 引脚→入口寄存器最大曼哈顿距离 |
| --- | --- | ---: |
| A | 西边，行 0 在北、行 15 在南，每行 64 bit 相邻分组 | 107.013 µm |
| B | 北边，列 0 在西、列 15 在东，每列 64 bit 相邻分组 | 254.245 µm |

2048 个数据输入均找到对应入口寄存器；没有引脚→入口寄存器超过 1 mm 的数据支路。
此检查不意味着后续整条控制/数据流水已经合格。控制寄存器→所属 tile token 引脚仍有
A 最大 3871.864 µm、B 最大 3690.228 µm 的异常，需独立修复。

## −53.41 ns 的具体路径

起点为北侧 `tile_row[0].tile_col[1].tile/read_data[198]`，对应 C 第 0 行、第 7 列的结果 bit 6。
终点为 `gather_slot[3].gather_group[0].gather_cell[7].gather_lane/gather_data[6]`。

| 位置/路径部分 | 坐标或报告增量 |
| --- | --- |
| tile 输出引脚 | (5199.965, 9776.272) µm |
| 第一个 gather AO22 输入 | (5240.069, 5068.035) µm |
| 以上支路曼哈顿距离 | 4748.341 µm，无中间缓冲 |
| 最终 gather FF 的 D 引脚 | (5208.184, 4575.555) µm |
| tile 输出到 AO22 输入的线延迟 | 35394.29 ps |
| AO22 门延迟 | 14681.75 ps |
| 数据到达 / 要求时间 | 63681.86 / 10268.80 ps |
| setup WNS | −53413.05 ps，确为 WNS，不是 TNS |

约 4.75 mm 的几何长度乘以平台信号电容得到约 787 fF，与报告的 790.53 fF 负载量级一致。
因此不是报告中无来源的 1000 倍缩放。北部结果被集中接到中部逻辑是直接可观察的布局错误。

报告里的 AO22 输入 slew 是 112002.41 ps；其 Liberty 的 input_net_transition 表最大仅 320 ps，
超出约 350 倍。tile 输出负载 790.53 fF 也超过宏模板的最大 92.16 fF。
这些极端条件下的延迟属于大幅外推，不能解释为可靠的实际硅延迟或最终工作频率。

原始报告：[v93 STA](/mnt/ubu_3T/ic_bcmk_orfs_asap7/flow/results/asap7/npu_systolic_matmul_16x16/ic_t10_candidate_top_v93_clean_controls_m7_wc_p1000_seed11/placement_clock_estimate.rpt:990)。

## 流程失误和后续约束

顶层配置关闭了 `GPL_TIMING_DRIVEN`，并覆盖默认 `repair_design_helper`，
以避免先前宏边界修复的大量缓冲扩张。替代流程主要针对命名控制树；后续支路修复也只覆盖选中的网络。
结果数据长线和部分低扇出但跨芯片的控制支路没有受到完整约束。
合法放置、零 overlap、选中支路长度达标不能替代全 DUT 的电气和时序验收。

新的 transport RTL 已将结果寄存器及逻辑按所属 tile 输出锚定；同网表 v98 的结果支路最大几何长度
降至 1065.666 µm，但仍不代表时序收敛。v98/v101 的 pre-CTS 控制路径诊断仍失败。
v102 是待运行的边界寄存器/控制组合逻辑局部化候选，没有 CTS 或布线验收数据。

下一步验收应同时检查完整信号网络的距离、负载、slew 和时序，而不能只筛选高扇出。
长距离结果传输须保留局部接收寄存器，配合缓冲与分段流水；保持持续吞吐和固定功能门禁。
未建 CTS 的候选使用理想时钟进行数据路径诊断，CTS/布线完成后再报告传播时钟的正式时序。
不修改 1 GHz 目标、I/O 约束或 M6/M7 时钟政策来掩盖失败。
