# T10 分散输入/输出候选

## 用户确认的实现自由度

输入与输出的数据切片可分散布置，没有数据寄存器集中或独立 gather 级的要求。
不改变双 1024-bit/拍输入、四行/拍输出、按块行顺序、同拍原子握手、背压保持、
1 GHz、资源上限及完整 256 PE 评估范围。

## 新架构

- 输出槽 g 对应物理 tile 行 g，负责逻辑行 4g..4g+3。
- 同一 tile 行的四个 tile 列分别驱动该槽的四个 256-bit 切片。
- 每 tile 有一个局部 egress 控制器、本地四行选择及输出队列。
- 不再让每个输出槽从全阵列的所有 16 行选取数据，不再跨四个 tile 行做宽数据 OR。
- 上一 tile 行的 retirement 指针只传向同一 tile 列的下一 tile 行，用于保证块内行顺序。
- 不同矩阵块可同时占据不同输出槽，保留每拍 4/2/1 行稳态输出的目标。
- 全局输出有效掩码在背压时锁存，各本地队列按实际外部槽握手推进。
- 所有既有 PE、tile、数学及结果 bank 模块正文完全不变；新增 egress helper。

## 物理候选流程

`t10_place_transport_spatial.py --distributed-egress` 将各输出数据切片放到所属 tile 旁的 M7 信号引脚网格，
并把 egress 状态与局部选择放在所属 tile 的通道中。A/B 数据入口寄存器、波前错位链与控制寄存器
按所属行/列的真实端点锚定，禁止通用位置迭代移动这些寄存器到芯片中央。

OpenROAD 支持内部二维引脚网格，见[官方 Pin Placer 文档](https://openroad.readthedocs.io/en/latest/main/src/ppl/README.html)。
这里的引脚是 benchmark 模块的物理接口；没有封装焊盘的约束。信号引脚仍受 200 ps I/O 延时、
合法金属形状、宏避让、实际布线和完整 DUT 时序约束，不能将跨区数据传输的代价从内部评分中隐藏。
分散物理端口政策尚需纳入通用评测流程后才能发布正式基线。

所有流程仍限一个自有 OpenROAD，遵守共享主机内存和优先级规则，时钟层保持 M6/M7。
新的全信号支路修复选项包括低扇出长线，排除时钟/复位，并独立反向核验每条正极性缓冲链的原始源。
当前没有宣称 CTS、布线、功耗或正式 PPA 已收敛。
