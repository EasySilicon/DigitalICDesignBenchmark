## 物理流程

```bash
python3 evaluator/t10_backend/v1/run_layout.py \
  --orfs /path/to/OpenROAD-flow-scripts --work /path/to/new/work \
  --seed 29 --block fp0
```

每个种子依次构建 `fp0/fp1/fp2/int/cpa/pe`，另一个种子将 `--seed` 改为 `47`。内部宏必须先完成并导出同种子的 LEF/Liberty，才能构建 PE。输出使用独立的 `ic_t10_v1_v15_seed*_…` 名称，不覆盖原始 v15 检查点。默认四线程，内部宏的虚拟地址上限为 30 GiB；新 PE 流程通过 systemd 用户控制组对整个构建进程树设置 32 GiB 实际内存硬上限、禁止交换，并限制分配器 arena 为 2，不再把虚拟地址空间当作 RAM。需要可用的 systemd 用户会话和 memory 控制器；控制组创建失败就停止，不退回无限内存运行。初始详细布线最多 20 轮；资源与流程完成记录不等于收敛合格，仍须逐项检查有效 DRC、连通、提取后时序与约束覆盖。固定参数下的残余违例需单独定位处理，不能盲目追加搜索后冒充已通过。

独立种子可在宿主资源允许时并行；同一种子的构建互斥。完成标记保存最终输出大小和 SHA，重复调用必须在锁内核对输入、输出后才跳过，不能并发覆盖同一 variant，也不能把缺少输出哈希的历史标记直接当作可复用结果。这只协调独立流程，不改变种子、工具线程数或布局参数。

种子 29 在 30 GiB 和 31.75 GiB 两种虚拟地址上限下，均于第 13 轮发生内存分配失败；后一次峰值驻留内存为 29,286,036 KiB。`resume_after_oom.py --ram-cgroup` 纠正限制方式，对整个构建进程树直接执行上述 32 GiB 内存硬上限。它核对原始输入并保留两次失败记录，从保存的全局布线点重新详细布线，不恢复未保存的第 13 轮状态，也不增加轮数或更改设计约束。这次恢复已完成原定流程；其最终残余 DRC 另行做固定坐标的局部修复，不能把“工具运行结束”当作收敛。

seed 47 在详细布局后有一个转发寄存器超出原有区域左边界 40 DBU（0.04 µm）。`resume_after_placement.py` 与 `repair_seed47_placement.tcl` 仅针对这份已保存的失败布局：将该单元右移一列、上移两行（54/540 DBU），不改区域、朝向、单元类型或连接，也不重跑全局布局。原生 `check_placement` 已通过，68,837 个实例的位置、单元与连接对照确认只发生该处位移。失败日志、失败 ODB、修复脚本及宏视图的哈希均保留；修复后的布局继续走原有 CTS/布线流程，不等于最终 DRC、时序和功耗已经合格。

`complete_seed.py` 跟踪每个种子各自的生产进程及启动时间，等待其真实完成后依次做物理核验、完整活动采集、活动合并和功耗计算。任一步失败即停止该种子的资格流程；一个种子失败不应让另一个种子的队列失去跟踪。即使单种子全部通过，也不宣称三种子基线已完成。

`verify_physical.py` 对 PE 和五类内部宏逐一复核，输出独立的单种子资格记录：

```bash
python3 evaluator/t10_backend/v1/verify_physical.py \
  --seed 29 --orfs /path/to/OpenROAD-flow-scripts --work /path/to/new/work \
  --gc-plugin /path/to/abi-matched/t10_manual_v15_gc_full.so
```

检查插件的编译依赖及原生检查范围说明见[上级说明](../README.md)。seed 11 另须传入 `--seed11-repaired-final`，指向修复后重新提取的最终检查点目录。其 WC 宏库严格匹配历史记录中的五个哈希；同目录较早导出的 `_wc.lib` 不能替代历史实际使用的 `.lib`。新种子的 `_wc.lib` 则由各自最终 ODB/SPEF 重新导出。

完整连通检查使用 `check_connectivity_full.py`，由 `verify_full_geometry.py` 对 PE 和五类内部宏统一调用。它读取最终 ODB，合并同层接触金属、实际过孔和管脚形状，要求每条信号网的全部金属和端点形成单个连通分量；只排除 VDD/VSS，不写回数据库。旧 `check_connectivity.py` 为保留历史记录而不变，但其路径迭代器会漏掉显式 RECT 补丁，不能单独证明最终连通。新实现补充解码这些金属矩形，并用附着、悬空两类原生测试验证这一差异。不能把依赖布线运行态的内部接口直接用于重载检查点，再将工具异常当作有效连通结论。

## 固定坐标的局部修复

原始布局布线结果、完成标记和失败报告均保留。修改仅涉及指定网络的金属和过孔；完整不变量审核对照所有网络，确认逻辑、布局、库单元、端口及宏障碍未变。修复后重新提取寄生参数，再检查时序和全 PE DRC；不能沿用旧 SPEF，也不能把原始报告改成零违例。

种子 29 的确定性复现入口为 `manual_seed29_final.tcl`，分别加载 `manual_seed29.cc` 与 `manual_seed29_secondary.cc` 编译的插件。脚本从原始最终 ODB 一次性应用 11 条网络的固定局部修改，不调用布局或布线搜索。种子 47 使用 `manual_seed47.cc` 的 `apply_local` 模式；早期 `apply` 原型违反金属矩形规则，不能用作最终结果。插件依赖锁定版本的 OpenROAD/OpenDB 私有头文件，必须按相同 ABI 编译，不能直接跨工具版本复用二进制。

`inspect_region.py` 和 `inspect_drc.py` 的几何诊断包含普通布线、RECT、宏障碍、管脚以及 SWire 电源线/过孔，避免把电源轨误判为空闲通道。`plan_corner_bridge.py` 只在有限范围内研究净空、生成待审核的坐标，不改数据库，也不判定 DRC 合格。`native_window.cc` 保持原生内核、分块网格和检查上下文不变，仅用于快速核对修改区域；最终仍须完整检查整个 PE，不能以局部检查代替。

`install_manual.py` 只接受绑定原始/修复 ODB 的完整不变量审核和原生失败对照；寄生重提取、setup/hold 非负且 TNS 为零后，才归档原件并安装修复版。安装记录本身不代表物理或功耗已经通过，后续必须运行完整验收队列。

## 完整门级模型与活动采集

`power_gate.mk` 只负责将完整 DUT 的外层逻辑映射到门级，保留 tile 层次并以 PE 为黑盒。随后补入对应种子的真实 PE 与内部宏门级网表，形成完整、无功能黑盒的门级仿真模型。

```bash
python3 evaluator/t10_backend/v1/run_gate_activity.py \
  --seed 11 --label activity --staged --pe-only-trace --windowed-saif \
  --orfs /path/to/OpenROAD-flow-scripts --work /path/to/new/work \
  --gate-shell /path/to/mapped/full_dut_shell.v
```

程序使用固定的 200 块 `T10-power-v1` 负载，在 1 GHz 下检查全部 51,200 个输出点、协议和时延，然后收集原生 SAIF。Verilator 全量读取大型门级模型会触及内存上限，因此 `--staged` 先仅按端口和依赖关系生成分层构建计划，再从完整真实网表逐块生成 C++，最后才编译和链接可执行文件。占位源只用于构建规划，不得编译或参与仿真；每个真实模块及编译参数均留存哈希。不放宽内存限额，不把 RTL 仿真当作门级测量。

`merge_pe_saif.py` 要求找到完整 256 个 PE、九个内部宏，以及每个 PE 相同的网络集合。它累计各实例的驻留时间和切换数，并把 SAIF 持续时间乘以 256，得到无整数舍入损失的等权平均活动。它不会把单 PE 功耗乘以 256，也不会凭部分实例推定全阵列活动。

`saif_window.py` 针对固定版本原生 writer 的延迟打开问题，在构建目录编译单独的运行库和可执行文件：起点使用实际打开时间，首次采样只初始化电平，不算切换。不修改安装目录或门级模型；保存原版、修正版源码及可执行文件哈希。小型原生回归验证延迟 2.1 ns 后采集 3 ns 时，持续时间确为 3 ns，常高/常低信号切换数为 0，时钟和数据的驻留时间、切换数准确。之前被拒绝的活动文件与日志完整保留，不能用于正式功耗。

`measure_power.py` 使用该活动分别读取单 PE 和九个内部宏的同种子 ODB/SDC/SPEF，以 TT 库测量功耗；外层扣除宏摘要功耗，宏内部独立求和，防止漏算或重复计算。数值、活动来源、1 GHz 时钟、256 实例覆盖、至少 95% 活动注释率任一不合格即拒绝输出合格功耗。三个种子的物理与功耗结果全部通过后，才能组装正式基线并提交。

固定 OpenSTA 的 [SAIF 词法规则](https://github.com/The-OpenROAD-Project/OpenSTA/blob/76c4d6df3537ccce331b5caa812196c3330ba7c4/power/SaifLex.ll)不接受网络标识符中的 `/`；[读取实现](https://github.com/The-OpenROAD-Project/OpenSTA/blob/76c4d6df3537ccce331b5caa812196c3330ba7c4/power/SaifReader.cc)还会将网络名当作引脚名查询。因此 `saif_activity.py` 与 `import_saif_activity.tcl` 按实际物理网络精确匹配，把 SAIF 的切换频率、驻留比例写入所有相连引脚，使用相同的原生活动 API。不会将常量的零切换替换成默认活动；不使用通配匹配；除 VDD/VSS 外，缺失物理网络或多义映射均失败。另行检查时序单元全部引脚的活动注释率，至少为 95%。原始 SAIF、平均 SAIF、网络活动数据和映射审计均保留。

## 三种子汇总与可移植报告

`assemble_baseline.py` 逐项核对三个种子的实际物理、完整几何、门级活动和功耗记录及原始文件哈希，全部通过后才输出测量记录、计分参考值及评测代码清单；它不会自行修改正式基线文件。三组数据缺一不可，单元测试通过也不能替代真实测量。

`export_bundle.py` 在汇总通过后归档小型原始报告，保持其内容和哈希不变，并提供原路径到随仓库副本的索引。ODB、SPEF、SAIF 等大型文件仅保留大小与哈希，因此报告包不是包含所有 EDA 数据和工具的镜像。检查随仓库保存的材料不依赖原宿主挂载目录：

```bash
python3 evaluator/t10_backend/v1/export_bundle.py --verify /path/to/report-bundle
```

只有三个种子的真实测量和最终汇总全部通过，才能将正式参考基线标为完成并提交。
