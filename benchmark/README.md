# Digital IC Design Benchmark for Agents

[English](README.en.md)

本目录定义十道数字 IC 工程交付任务及其公共评测契约。任务要求可综合 RTL、自建验证、PPA 优化尝试和可复现交付；成绩依次比较功能、PPA 和完成时间。项目动机与能力覆盖见[项目首页](../README.md)。

当前套件为 `ic-delivery-rtl-v0.3`，仍处于预发布阶段。十题参考基线已具备，其中 T10 为单 PE 测量；历史 pilot 成绩见[结果目录](../results/README.md)。

## 通用验收规则

正式验收通过题卡端口观察 DUT，由评测方独立生成输入并计算预期结果，不调用候选 `run.sh` 或相信自报 PASS 来判定 RTL 正确性。公开冒烟、候选自测与正式验收分别记录。

功能失败按[计分映射](../evaluator/score_rules.json)保留已取得的子项分。T05 包含 CDC 结构检查；T10 包含完整 256-PE 的网格、局部累加、资源和持续吞吐检查，单 PE 正确不能代替整机验收。v1 T10 使用严格数值 profile，MMA 宽松诊断不替代正式判分。

执行器和公开冒烟入口见 [evaluator](../evaluator/README.md)。CPU 专项与 NPU 测试要求分别见 [T09 验收](tasks/T09/acceptance.md)及 [NPU 验收计划](npu-validation.md)。

## 验证与交付契约

| 制品 | 要求 |
| --- | --- |
| `rtl/`、`rtl/files.f` | 可综合源码；filelist 每行一个 `rtl/` 内相对路径，不含绝对路径、`..` 或命令选项 |
| `verif/` | 自建、可执行、会比较期望与实际值的验证环境 |
| `run.sh` | 从工作区根目录执行，无交互、不下载依赖；真实通过返回 0，失败返回非零 |
| `results.json` | 实际自测生成；包含 `tests`、`tool_versions`、`elapsed_seconds`，测试项含 `name`、`passed` 和实际整数 `seed` |
| `README.md` | 复现命令、验证范围、已知限制、设计取舍与实际 PPA 探索记录 |

`run.sh` 支持 `BENCH_SEED`，缺省值须固定并写明；测试实例以 `(name, seed)` 唯一标识，相同种子可复现。模型开发阶段无需扫完所有评测种子；交付后由评测方复现。T09 使用同一交付契约，官方 ISA 验收另由评测方加载 ELF 并采集提交记录。

PPA 探索记录允许如实报告失败或未改善；不要求每题都取得正向优化。候选不能用自己的 SDC、单元模型、报告或分数替换正式测量。

## 评测与评分方法

### 资源约束

统一分配为 16 vCPU、40 GiB RAM、100 GiB 可写盘，无 GPU；token 只统计，不设累计上限。模型推理、编译、仿真、EDA 和重试计入开发时间；主机准备、排队和交卷后的独立评分不计入。

正式运行使用 [benchmark.runner](runner/README.md)，每题独立会话和工作区，候选材料与主机验收隔离。模型、档位、语言、Skills、工具和协作策略按试验配置记录，不同条件的结果分别解释。准备器只向候选复制单题公开材料：

```bash
python3 benchmark/prepare_trial.py T03 /path/to/empty/T03 --language en
```

### 分层评分与排名

| 分量 | 上限 | 条件 |
| --- | ---: | --- |
| 功能 | 50 | 按各题验收组计分；题卡中的 F/P 原始子项均属于功能，合计 75 后归一化 |
| PPA | 50 | 功能全通过，且综合、必要结构和测量来源检查合格 |
| 时间 | 5 | 功能全通过且 PPA 大于 0；`5 × (1 − t/T_max)`，裁剪到 0–5 |

T08/T10 按其冻结的组内比例计分；T09 周期组有专属分档；其他任务按各自全分、半分、零分和安全门禁规则执行。缺失或不合法的评分输入报错，不补成通过。

交付扣分每题最多 10 分，具体根因及归因见 [delivery-policy.md](delivery-policy.md)。`显示分 = max(0, 功能 + PPA + 时间 − 交付扣分)`；套题显示分按任务权重求和，缺项不重新放大权重。

单题排序依次比较功能分、PPA 分档、完成时间；分档宽度为 1.25 分。套题依次比较功能全通过题数、功能总分、全通过题的 PPA 档号总和，最后比较这些题的 `t/T_max` 总和。显示总分不替代分层排序。

已确认的候选功能失败影响对应子项，并关闭 PPA/时间资格；候选物理流程失败不抹掉有效功能分。评测器、工具或依赖故障不处罚候选，受影响分项保持待评。`0` 表示已判失败，`null` 表示尚无结论。

## PPA 测量与评分

使用锁定的 Yosys、ASAP7 和 OpenROAD，目标为 1000 ps / 1 GHz。T01–T09 测完整 DUT；v1 T10 测单 PE，整机仍须通过功能、结构和吞吐验收。T08 包含固定 SRAM 模型，T10 有单 PE 专属物理参数；参考与候选必须采用同题相同测量范围和参数，详见 [T08 契约](tasks/T08/task.md)、[T10 单 PE 契约](tasks/T10/ppa.md)、[来源锁定](sources.lock.yaml)及[参考基线](ppa-baselines.json)。

### 测量参数与范围

| 参数 | 当前契约 |
| --- | --- |
| 库与角 | ASAP7 7.5T RVT NLDM，标准单元 WC 时序、TT 活动功耗；T08 SRAM 使用声明的 TT 研究模型，不能声称全设计 WC 签核 |
| 时钟与 I/O | 各域 1000 ps，I/O 延迟比例 20%；T05/T08 的异步时钟域分别约束，不切除域内有效路径 |
| 驱动与负载 | 固定 `BUFx2_ASAP7_75t_R` 输入驱动、3.898 fF 输出负载 |
| 利用率与密度 | T01–T09 为 10% / 0.60；T10 单 PE 为 24% / 0.24，内部宏按其专属契约 |
| 存储映射 | T02/T05/T07 小型存储及 T09 寄存器文件映射为标准单元；T08 使用指定 SRAM，T10 内部宏按单 PE 契约计入 |
| 重复测量 | 布局种子 11/29/47；当前流程随机化布线，不能把三次布线称为三次独立随机放置 |

约束由评测方生成，候选不能修改。面积排除填充单元和测试平台，包含实际放置的约定宏及其未使用容量。参考与候选的比较必须使用同题相同配置。

### 固定功耗负载与有用操作

负载固定版本和事务分布，输入必须合法，输出仍须自检。能耗分母不能在不同候选间改变：

| 任务 | 一个有用操作 |
| --- | --- |
| T01 | 一个实际输出的 10-bit 对齐符号 |
| T02 | 一次成功读出，且对应先前接受的写入；复位丢弃项不计入 |
| T03 | 一次完成的 APB 访问，窗口内定时器活动计入总能耗 |
| T04 | 一次成功输出传输 |
| T05 | 一次成功读出，且对应先前接受的写入；两域以规定时钟和相位运行 |
| T06 | 一次完成的 AXI 读或写事务 |
| T07 | 一次完成的 CPU 请求；命中、缺失及读写比例由固定负载确定 |
| T08 | 一个接受的 TX 帧体字节或交付的 RX 帧体字节；计入固定拒绝/恢复负载和 SRAM 活动 |
| T09 | 一条正常退休指令；指令和等待分布固定 |
| T10 | 单 PE 完成一个矩阵块所对应的点积；完整 DUT 运行规定负载，等权汇总全部 PE 的活动并计入内部宏 |

`N_ops` 来自端口接受事件、输出事件或 CPU 退休事件。初始复位、装载和测试平台初始化不计入窗口；负载内的停顿及运行中复位按相同规则计入所有候选。相同操作量下更长的窗口会增加每操作能耗。有效活动标注率至少 95%；T10 的单 PE 能耗不能冒充完整 NPU 能耗。

### 聚合与计分

面积包含实际逻辑、寄存器、缓冲、时钟单元及约定宏；功耗来自对应布线网表、寄生参数和固定自检负载的活动测量。能耗按 `E = P_avg × 测量时长 / 有用操作数` 换算，不能用 RTL 行数、网表行数或不同工作负载替代测量。

三布局种子的面积、延迟、能耗取中位数，setup/hold 裕量取最差值，DRC 取最大值；有效种子保留和超时处理遵循[物理评估政策](physical-runtime-policy.md)。功耗仿真编译每种子另限 T01–T09 20 分钟、T10 40 分钟，按[统一编译预算](power-compile-policy.md)执行，两种时限不得混用。

令 `S/H` 为最差 setup/hold 裕量，时间单位为 ns：

```text
R(x)    = min(2, max(0, x))
D_eff   = D + max(0, -H)
D_setup = T + max(0, -S)
P_base  = min(50, 35 × R(A_ref/A)^0.35 × R(D_ref/D_eff)^0.35 × R(E_ref/E)^0.30)
PPA     = P_base × (T/D_setup)^4 × (有 DRC 则 0.5，否则 1)
```

参考实现得 35/50 分；候选负时序裕量连续扣分，有 DRC 时统一减半。完整有效测量、活动标注和来源校验仍是计分前提。当前入口为预算 wrapper，历史冻结入口仅用于旧基线复现；见[统一入口说明](power-compile-policy.md)。

## 领域与难度覆盖

本节说明[任务卡](#共享任务规则)为何能检验不同的数字 IC 设计能力。它是**需求覆盖论证**：每项能力都对应题面和独立验收组；当然这10道题目肯定不可能覆盖全部芯片研发可能的主题与流程。

### 逐题映射

| 难度假设 | 题目／时限 | 主要设计领域 | 主要工程难点 | 独立验收证据 |
| ---: | --- | --- | --- | --- |
| 1 | T01 SerDes RX comma aligner／30 分钟 | 高速串行链路 PCS、符号同步 | 跨切片 bit 窗口、comma 训练、字重组、失锁与重锁 | AC-05–08B；随机相位、bit slip 与 marker 注入 |
| 2 | T02 同步 FIFO／1 小时 | 流式缓冲、参数化存储 | ready/valid、空满、同拍推拉、非 2 次幂回绕 | AC-09–15；深度 3/8/16、位宽 8/32 |
| 3 | T03 APB4 定时器／90 分钟 | 寄存器外设、计数状态机 | APB setup/access、字节写、W1C、中断、事件优先级 | AC-16–20；逐拍寄存器模型 |
| 4 | T04 轮询仲裁器／90 分钟 | 多端口流控、资源调度 | 长期公平性、仲裁状态、背压保持 | AC-21–25；N=4/8 持续竞争 |
| 5 | T05 异步 FIFO／2 小时 | CDC、双时钟缓冲与复位 | Gray 指针、双级同步、保守空满、双域恢复 | AC-26–31；动态时钟比和 CDC 结构检查 |
| 6 | T06 AXI4-Lite/APB4 桥／2 小时 | 片上互连、协议转换 | AW/W 解耦、读写并发、APB 等待、错误映射 | AC-32–37；独立双端记分牌 |
| 7 | T07 写回缓存／2 小时 | 存储层次、数据一致性边界 | tag/index、脏行替换、写分配、字节使能 | AC-38–43；独立字节内存模型 |
| 8 | T08 MAC 修复／2 小时 | 以太网 MAC、存量 RTL 维护 | 长规格理解、边界修复、VLAN 策略、CDC 与元数据 | 37 个场景 × 3 个种子；270 次压力运行 |
| 9 | T09 RV32I 五级 CPU／2 小时 | 处理器微架构、ISA 实现 | 取指至退休延时、旁路、停顿、冲刷、精确异常、按序提交 | CPU-ACT/DIR/DIFF/PIPE；逐条延时与至少 10 万条随机退休差分 |
| 10 | T10 16×16 持续双 1024-bit/拍脉动阵列／4 小时 | NPU/DSP 算术、数据格式、空间阵列与流式吞吐 | 16×16 向量 PE 邻接转发、4/8/16 拍块启动间隔、四行槽/拍带 ID 输出、FP8/FP4/MX 数值、背压信用、舍入与物理成本 | MM-INT/F16/F8/F4/MX8/MX4/PROTO/SYSTOLIC/CORNER；冻结参考已通过 2,752 块流式验收，14 个可编译缺陷变异体已检出，单 PE 三种子物理与正式活动功耗已通过 |

### 覆盖范围的可核查结论

- **多类主要领域**均有专门题目：单时钟状态控制、高速串行链路 PCS、流式缓冲与仲裁、片上总线与外设、CDC、存储层次、处理器、NPU/DSP 矩阵算术。T10 补上乘法阵列和低精度浮点/块缩放。
- **时钟与状态尺度**从单寄存器、串行 bit-buffer 与对齐状态，到单时钟多状态、双异步时钟、五级流水线和 2D 波前阵列；检验的不是同一种 RTL 模板的十个变体。
- **接口与协议**包含连续串行切片、ready/valid、APB4、AXI4-Lite、line 后端和 CPU 指令/数据接口；至少三题专门施加背压、乱序到达的独立通道或外部等待。
- **横向能力**包括参数化（T02/T04/T05）、复位及事件优先级（T02–T10）、独立模型验证（全部题）、统一 ASAP7 布线后 PPA 评估（已校准题）。T10 的单 PE 物理与正式活动功耗基线也已完成。
- **难度结构**预置 1–3、4–6、7–9 三档及第十题压力项；逐题时限为 30 分钟至 4 小时，十题合计 18 小时 30 分钟。

### 后续可能扩展

未来可能扩展的题目会包括：NoC、DDR/高速 I/O、DFT/扫描、低功耗多电源域、安全 IP、模拟/混合信号和真实流片签核。
