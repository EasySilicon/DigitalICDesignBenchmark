# T10 工程质量门禁与商用差距

本文件区分 **参赛候选**、**评测方独立参考**、**开源工艺下可实现 IP** 和 **量产签核 IP**。功能分通过只证明当前端口事务在指定数值契约下正确，不能替代综合、物理收敛或量产签核。ASAP7 是[预测性 PDK](https://github.com/The-OpenROAD-Project/asap7/blob/main/README.md)；OpenROAD 可做详细布线和寄生提取，但本 benchmark 的结果只能表示统一公开工艺上的相对工程质量。

## T10 正式发布的自动硬门禁

这些门禁对参考 RTL 和所有参赛提交使用同一题面、工具镜像、资源上限与物理参数。任一项缺失时只报告试运行结果，不发布 T10 正式成绩。

| 门禁 | 可复核通过条件 | 自动证据 |
| --- | --- | --- |
| 数值与协议 | 十种模式；所有合法测试块的 256 个结果均通过独立精确 oracle；包括 MX scale 0/254/255、跨 32 元素组、单项溢出后有限抵消、binary32 有限/无穷边界、真∞优先级、连续模式切换、输入暂停、背压和运行中复位 | 固定种子及定向向量、逐块逐元素结果、失败时最小坐标与输入复现；协议组和脉动组也不能容忍错误数值 |
| 持续吞吐 | 无背压时 FP4/FP8/FP16 块启动间隔分别为 4/8/16 拍，A/B 连续各 1024-bit/拍；四个带块 ID 的输出行槽在稳态分别每拍交付 4/2/1 行；混合格式长流不串块 | 至少 256 个 FP4 块、各模式 64 块和 512 块混合流的逐周期计数与完整结果；单块突发通过不足以达标 |
| 阵列结构 | 256 个局部 PE、两条正交寄存邻接链、局部累加反馈和所有 lane 对结果的依赖；不得依赖信号名或人工审核 | Yosys 展开网表检查、阳性参考与结构缺陷变异体 |
| 验证有效性 | 独立参考全组通过；至少 12 个有效缺陷变异体覆盖数值、位序、scale、邻接链、握手、复位；参赛者自带验证在隔离交付检查中可重复运行 | 参考/变异体检出矩阵、版本与种子、参赛交付日志 |
| 可综合性 | 在 16 vCPU、32 GiB、100 GiB 上完成统一 Yosys 映射；无功能黑盒、未预期锁存器、未约束时钟或数据路径；映射后网表运行代表性十模式功能回归 | 资源峰值、映射日志、单元统计、网表回归报告 |
| 物理可实现性 | 用统一 ASAP7/ORFS 参数完成种子 11/29/47 的放置、CTS、详细布线和 RC 提取；全部受约束路径满足 **1000 ps / 1 GHz** 目标，setup/hold 违规和详细布线 DRC 违规为 0；不允许通过删除路径或例外掩盖失败 | 每种子原始时序、检查覆盖率、DRC、布线与提取日志；基础设施失败统一重跑 |
| 功耗与 PPA | 三种子固定十模式工作负载都经独立 oracle 检查；活动注释率 ≥95%；记录面积、关键路径、平均功率、每完成块能耗和相应评分 | 门级波形/SAIF、OpenROAD 报告、工作负载 hash、参考三元组；缺项不得估分 |
| 参考独立性 | 参考 RTL 从题卡和公开数值规范另行实现，不能由参赛试跑候选修补后改名；在其功能、物理与变异体证据齐备后才冻结基线 | 版本历史、参考源码与评测记录；基线发布前可复核，逐提交评分全自动 |

上述物理检查应在最终工具镜像中验证可用并按[统一 PPA 方法](ppa.md)冻结；如果九题既有参考值所用流程缺少新增的 setup/hold 或 DRC 证据，应同一流程补跑九题，不能只对 T10 改用更宽松或更严格的物理参数。面积与能耗的绝对可接受上限必须先由独立参考和应用场景校准，再写入冻结版本，不能从一次失败候选推算。

## 商用 IP 仍需的工作

新版题卡已经用 `in_start`/块 ID、四槽输出和逐模式启动间隔把**持续 1024-bit/拍输入及块间重叠**列为硬要求。旧候选与旧测试平台均不能用于新版评分；新版公开持续流冒烟、私有流式驱动和独立参考 RTL 已写出，参考的 2,624 块流式回归通过，已检出 14 个可编译缺陷变异体，仍须 PPA 基线完成端到端校准。持续吞吐仅在 `out_ready=1` 的窗口保证；背压时允许在块边界按信用停收，但已接受块不得中途失约。

即使以上开源门禁全过，量产仍需要目标代工工艺的 PVT/片上变化与 SI 时序、真实 SRAM/寄存器文件宏、DFT/扫描、等价性、功率与时钟意图、IR/EM、物理 DRC/LVS、良率与系统集成等证据；具体项目按目标产品和工艺选择。公开预测工艺不能代替这些签核，也不能让 benchmark 宣称某设计已经具备流片资格。
