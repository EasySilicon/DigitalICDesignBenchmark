# T10 PPA 评测契约

T10 的完整门级网表远大于其余任务。评测仍覆盖完整 16×16 DUT，但采用候选设计自身的层次化实现，而不是把 256 个 PE 全部展平后放在一个 OpenROAD 数据库中。该方法只改变物理实现的分块方式，不按参考 RTL 的模块名或版图数据匹配候选设计。

## 自动发现的物理层次

候选设计必须保留以下可综合层次，模块名可以自行选择：

- 顶层包含同一种 4×4 tile 模块的 16 个实例；
- 每个 tile 包含同一种 PE 模块的 16 个实例；
- 全设计共 256 个 PE；
- PE 间仍须通过独立的网表结构检查形成两组正交 16×16 寄存传递链，并具有本地反馈累加。

该层次只作为 **T10 PPA 入榜门禁**。端口功能分仍由完整 DUT 的独立测试决定。评测器从 Yosys 展开结果中按实例数量、端口形状和连通关系发现 tile 与 PE，不要求 `tile`、`pe` 等固定名称，也不使用参考 RTL 层次与候选源码做文本比较。

## 三种子物理流程

布局种子固定为 `11/29/47`。每个种子独立完成三级实现：

1. 将候选 PE 综合、放置、CTS、详细布线和 OpenRCX 提取，导出同一检查点生成的 LEF、Liberty、门级网表、SDC、SPEF 和 ODB；
2. 将该 PE 作为硬宏实现候选 4×4 tile，完成同样的布线后检查并导出 tile 视图；
3. 将该 tile 作为硬宏实现完整顶层的 16 个 tile 实例，完成顶层详细布线和提取。

所有层级均使用 ASAP7 RVT、WC、1000 ps、同一套 I/O 延时和同一种子。信号布线使用 M2–M7，时钟树使用 M6–M7。宏抽象必须由该种子对应的已布线检查点生成；禁止跨候选、跨种子或跨 RTL 哈希复用物理宏。

每个种子必须同时满足：

- PE、tile 和完整顶层的 setup/hold WNS 均不小于 0；
- 三个层级的 OpenROAD 详细布线 DRC 均为 0；
- 所有受测时钟和 I/O 路径有约束；
- 宏 LEF、Liberty、ODB、SDC 与 SPEF 的来源哈希一致；
- 顶层实例面积包含 16 个 tile 宏，tile 面积包含 16 个 PE 宏，面积不重复累加。

正式延时取三个层级中最差的 `1000 ps - setup WNS`。正式面积取完整顶层数据库的总实例面积。GDS、LVS、IR/EM 和 foundry signoff DRC 不参与 benchmark 评分。

## 功耗与每块能耗

固定 200 块持续流 workload 先在完整候选门级模型上通过数值 oracle、协议和 1 GHz 时钟检查，并生成层次化活动数据。功耗按物理层次相加：

```text
P_total = P_top_shell
        + Σ P_tile_shell[i], i=0..15
        + Σ P_pe[i],         i=0..255
```

每一项使用相应种子的已布线 ODB/SPEF 和该实例作用域的活动数据；shell 报告排除其硬宏内部功耗，避免重复计算。等价实例的活动可以由评测器合并为带权平均后一次计算，但权重总数必须分别为 16 和 256，并保存合并前后的切换计数审计记录。被统计的时序单元活动注释率不得低于 95%。

每块能耗按 `P_total × workload 有效时间 / 完成矩阵块数` 计算。三个种子的面积、延时和每块能耗分别取中位数进入基线；任一种子缺失或任一物理门禁失败时，T10 PPA 基线不发布。

## 必须保存的机器可读证据

正式基线 JSON 至少包含：

- 冻结 RTL、文件列表、结构检查、workload 和评测脚本的 SHA-256；
- 工具版本、ASAP7 清单哈希、统一参数和布局种子；
- 每种子、每层级的面积、setup/hold WNS、DRC、约束覆盖和产物哈希；
- 每种子的总功耗、每块能耗、活动注释率与分层求和明细；
- 三种子聚合值以及所有原始报告的 SHA-256。

仓库中的 `ppa-baselines.json` 只保存评分所需的汇总和审计哈希。体积较大的 ODB、DEF、SPEF 和日志可以作为版本化发布附件保存。GDS 是可选审计产物。
