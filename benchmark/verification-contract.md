# 验证与完整交付契约

本契约随九题[任务卡](tasks.md)发给每个参赛 Agent。**每题的工作范围同时包含 RTL 设计、自带验证环境、修复缺陷和 PPA 优化。** Agent 可自由选择 SystemVerilog/UVM、SVA、cocotb、C++ 或组合实现 `verif/`；评测方的功能结论来自独立编写的验收器，与其 UT 框架无关。

## 参赛提交及本地入口

| 制品 | 必要内容 | 评测用途 |
| --- | --- | --- |
| `rtl/` | 可综合 `.sv/.v` 源码；单一约定顶层，所有设计功能经题卡端口体现 | 独立功能验收、统一 Yosys/OpenROAD PPA |
| `rtl/files.f` | UTF-8 文本，每行一个位于 `rtl/` 内的相对源文件路径；不含命令选项、宏、绝对路径或 `..` | 评测器安全地读取源码清单并自行编译 |
| `verif/` | Agent 自建的可执行自检，包括至少一个会判断预期与实际值的测试；T03–T09 应覆盖各自题卡主要行为类 | 检查完整验证交付，运行变异体诊断测试质量 |
| `run.sh` | 可执行、无交互的本地自检入口；默认从仓库任务工作区运行，不下载依赖 | 检查自检可重复执行，供 Agent 日常迭代 |
| `README.md` | 构建/运行说明、自检范围、已知限制、设计取舍和 PPA 优化记录 | 审计交付过程，不凭文字给功能分 |

`run.sh` 从工作区根目录调用；返回码 0 表示自检通过，非零表示失败。支持 `BENCH_SEED` 环境变量，未设置时用文档写明的固定默认种子；运行结果写入当前目录的 `results.json`。该文件至少含 `tests` 数组，每项包含 `name`、`passed`、`seed`；另含 `tool_versions`、`elapsed_seconds`。可以包含 UVM、断言、覆盖率、波形和详细报告，但不能要求评测器理解其内部格式。评测方分别运行两次相同种子检查结果可重现，再用其公开的故意错误样例确认自检确实失败。Agent 可以在时限内反复执行该入口，**这些运行均计入开发时间**。

T09 还须支持 `./run.sh --elf /absolute/path/program.elf`：Agent 的验证环境加载任意符合题卡内存布局的 RV32 ELF，运行至 `tohost` 或超时，返回 0 当且仅当 `tohost=1`，并在 `results.json` 给出 ELF SHA-256、`tohost` 值、是否超时与失败原因。**Agent 无需生成逐指令 trace 文件或实现 trace 采集器。** `--elf` 模式不得靠文件名、固定 PC 或预知程序输出判定 PASS。此接口用于验证 Agent 交付的 ELF 运行能力；官方 CPU 功能分仍由评测方自己的 ELF 装载器、总线模型、ACT4/差分程序取得。

Agent 可以使用预装 Yosys、OpenROAD、ASAP7 和 ORFS 脚本反复测自己的 RTL，并据此优化面积、布线后路径和能耗。`README.md` 记录至少一个优化候选与最终选择，以及实际运行的工具命令、配置 hash、测量值或失败日志。对小题和首次即最优的设计，允许保留原实现并说明测量证据；**不要求每题都证明正向改进**。正式 PPA 由评测方统一重跑，参赛者的 SDC、种子、报告和自测分数均不直接进入排名。

## 固定 DUT 连接规则

| 任务 | 顶层模块名 | 评测参数组合 | 外部连接 |
| --- | --- | --- | --- |
| T01 | `priority_encoder_8x3` | 无 | 题卡的 `in/out` |
| T02 | `serial_in_parallel_out_8bit` | 无 | 题卡的 `clock/serial_in/parallel_out` |
| T03 | `synchronous_fifo` | `WIDTH,DEPTH`：`(8,3),(8,8),(32,16)`；再做交叉组合 | 题卡的单时钟流接口 |
| T04 | `apb4_timer` | 无 | 题卡的 APB4、`irq` |
| T05 | `round_robin_stream_arbiter` | `N,WIDTH`：`(4,8),(8,32)`；再做交叉组合 | `in_data` 定义为 packed `logic [N-1:0][WIDTH-1:0]`，下标 `i` 为第 `i` 路 |
| T06 | `asynchronous_fifo` | `WIDTH,DEPTH`：`(8,8),(32,16)`；再做交叉组合 | 题卡的双时钟流接口 |
| T07 | `axi4lite_to_apb4_bridge` | 无 | 题卡的完整 AXI4-Lite 和 APB4 接口 |
| T08 | `direct_mapped_writeback_cache` | 无 | `clk,rst_n`、CPU 侧与 line 后端接口 |
| T09 | `rv32i_five_stage_cpu` | 无 | 题卡的存储器和提交观察口 |

端口名、方向、位宽、参数名及题卡时序语义均固定；不固定内部目录层级、源文件名、验证框架、事务类名、断言写法或流水线内部信号名。评测器从 `rtl/files.f` 只读源文件，用自身固定编译参数 `--top-module` 和参数覆盖进行 elaboration；禁止评测器在功能评分时执行候选的 `run.sh`、读取其 `results.json` 作为正确性 oracle，或调用候选自带驱动器/scoreboard。候选可以在 `rtl/` 内实现必要的子模块；这些子模块进入同一 PPA 流程。

## 官方验收器与参赛 UT 的关系

| 对象 | 谁实现 | 如何判断 | 是否进入正式功能分 |
| --- | --- | --- | --- |
| 自带 UT | 参赛 Agent | 入口是否运行、自检是否真实、变异体检出率及需求覆盖记录 | 作为交付准入和质量诊断；不替代独立功能分 |
| T01–T08 独立验收器 | benchmark 团队 | 行为题只看 DUT 端口握手/输出，按[验收组](acceptance.md)以外部模型判定；T06 另做 CDC 结构审查 | 是，F+P 共 75 分 |
| T09 独立验收器 | benchmark 团队 | 自有 ELF 装载器、存储器模型、ACT4、定向程序、逐条取指至退休延时、提交差分及五级结构审查 | 是，F+P 共 75 分 |
| 统一 PPA 流程 | benchmark 团队 | 固定工艺/约束/活动负载，布线后重测 | 功能全过且交付合格后计 20 分 |

每题都需要评测方的**独立、可自检的 UT 环境**，包括 CPU；ACT4 只能覆盖适用的 ISA 规则，不能检验题卡自定义总线、精确提交或五级流水线。评测方通过输入波形、事务和外部参考模型验收 RTL，故 Agent 的 UT 风格可以差别很大。严格的“**全部分数只看端口**”无法证明 T06 的双级同步器、T09 的真实五级结构和部分资源限制；这些项目必须辅以静态结构审查和有证据的复核。T06 已有[双级链检查原型](../evaluator/README.md#t06-双级同步结构检查原型)，但尚不足以完成整个 CDC 验收。审查规则、证据及复核记录须冻结，对所有系统一致。
