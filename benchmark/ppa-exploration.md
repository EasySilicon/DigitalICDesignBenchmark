# 统一 ASAP7 参数探索记录：第一轮

本页是 **2026-09-25 的试跑证据**，只产生试评分，不产生正式榜单分数。入口为 [`evaluator/ppa_probe.py`](../evaluator/ppa_probe.py)；九题使用独立参考 RTL、同一数值参数和本仓库 ASAP7 平台，从 Yosys 综合运行到 OpenROAD 详细布线、OpenRCX 寄生提取与最终时序报告。输入 RTL 的功能由私有验收器另行验证。共同 2500 ps 最坏角、三种子布线与 TT 功耗负载已完成；参考值见[机器可读清单](ppa-baselines.json)。

## 试跑配置

| 项目 | 本轮值 |
| --- | --- |
| ORFS / ASAP7 | 锁定 ORFS `1ec57da7bf0f1491190cbea2673c2c01fb3bc3ae`，仓库 `vendor/asap7`，应用 [`orfs-26q2-compat.patch`](../env/orfs-26q2-compat.patch) |
| 工具 | Yosys `0.69+150`，OpenROAD `26Q2-1164-g08f67ee5ec` |
| 库与角 | NLDM、RVT、ORFS `CORNER=BC` 即 FF；**尚非正式 SS 最坏角或 TT 功耗** |
| 约束 | 全题周期 750 ps、I/O 输入与输出各 150 ps；T06 两异步时钟同周期并切除异步跨域路径 |
| 物理 | 目标利用率 10%、放置密度 0.60、长宽比 1、边界 0.5；种子 11 传给 GRT/详细布线 |
| 综合 | ORFS Yosys 标准综合，`SYNTH_USE_SYN=0`，T03/T06 为 WIDTH=32、DEPTH=16，T05 为 N=8、WIDTH=32 |

`GPL_RANDOM_SEED` 未传入：锁定 ORFS 脚本会把它转换为 `global_placement -random_seed`，本机 OpenROAD 版本不支持该选项。三种子策略应只对本机支持的随机化阶段生效，或改用完全锁定且兼容的工具版本，再统一重跑所有题目。

## 结果

面积来自最终 ORFS `finish__design__instance__area__stdcell`；延迟为约束周期减最终 setup worst slack，包含最终路由 RC、I/O 约束及当前 FF 库角。两者仅供参数筛选，**不能代入正式评分公式**。

| 任务 | 布线/RC | 面积 μm² | 当前角延迟 ps | WNS ps | 观察 |
| --- | --- | ---: | ---: | ---: | --- |
| T01 | 完成 | 2.114 | 371.071 | 378.929 | 35% 目标利用率曾因最小 core 空间不足失败；10% 可布线 |
| T02 | 完成 | 4.899 | 237.734 | 512.266 | 顺序逻辑小核可布线 |

| T05 | 参数修正后完成 | 132.168 | 726.104 | 23.896 | 8 路、32-bit 参数组合 |

T08 的失败是共同周期候选不满足当前角的明确证据。后续需在全部参考设计上完成 SS 时序和 TT 活动功耗，并比较 2500/3000 ps 等共同周期候选及三个固定布局种子。不可单独放宽 T08 的周期；参考面积和能耗三元组也不能在此轮产生。

**参数脚本纠错**：首轮脚本曾把 T03/T05/T06 的顶层参数写入 ORFS 不识别的 `SYNTH_PARAMETERS`，实际映射的是默认配置，原先三项数字已撤销。修正为 ORFS 所用的 `VERILOG_TOP_PARAMS` 后，以上三项重跑了 Yosys 至详细布线和 RC。这个错误说明必须从最终门级网表核对端口位宽和存储规模，不能只看配置文件或流程成功状态。

T09 五级参考 CPU 的单独试跑采用相同 ASAP7/ORFS 流程、BC 角、10% 利用率、0.60 密度和种子 11，但周期为 1500 ps：详细布线与最终 RC 完成，单元面积 2199.040 μm²，WNS 125.115 ps，计算延迟 1374.885 ps，用时约 782 秒。由于周期不同，不能把该数字与上表的 750 ps 试跑合并排名；它只证明 T09 可进入统一周期的下一轮校准。

## 典型角功耗链路试跑

[`ppa_power_probe.py`](../evaluator/ppa_power_probe.py)已在 T01–T09 的一组参考布线网表上打通门级自检、VCD 切换活动、ASAP7 TT Liberty 与 OpenROAD `report_power`。九题的网表门级自检均通过，按 OpenROAD `report_activity_annotation` 统计的 pin 活动注释率均为 100%。T03/T05/T06 使用修正后的 32×16、8×32、32×16 网表；T07/T08 的门级测试需要在首次采样前明确给异步复位一个下降沿，功耗探针只在临时测试平台中补这个边沿。早期 CPU 探针使用 1,280 条正常提交的固定种子 ELF。探针现从测试记录或握手监视器自动计算有效操作数，避免占位值；T04、T05 和公开 T07/T08 负载分别测得 69、149、8、10 次操作，私有 T07/T08 长负载分别测得 255、648 次完成事务且自检通过。**这些仍是流程试跑，不能作为正式参考能耗**；正式功耗负载的分布、窗口及三种子重复性仍待冻结。

随后把九题都切到更长的评测方负载，并在同一 2500 ps WC 布线网表上测 TT 活动功耗。T01–T08 复用独立隐藏验收流；T06 的功耗模式保留三段异步时钟频率比，每段运行 1024 次目标传输；T09 使用固定的整数、访存、分支混合 ELF，按退休计数。以下仅是**种子 11 的量纲检查**：
