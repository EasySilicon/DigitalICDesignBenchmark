# PPA 测量与次级评分：Yosys + ASAP7 + OpenROAD

PPA 仅在任务的 F+P=75/75、交付合格且 RTL 可综合时计分；功能错误的低面积实现不获得 PPA 分。正式评估固定使用 **Yosys 综合映射 → ASAP7 7.5T 标准单元 → OpenROAD 布局、时钟树、详细布线、寄生提取及时序/功耗报告**，不单独运行另一套 STA 工具。[OpenROAD 官方流程](https://github.com/The-OpenROAD-Project/OpenROAD-flow-scripts/blob/master/docs/user/UserGuide.md)和[OpenRCX 文档](https://openroad.readthedocs.io/en/latest/main/src/rcx/README.html)给出这些阶段的能力。综合后的 Yosys 面积/时序只作为诊断；排名使用**布线后**指标。ASAP7 是预测性公开工艺，不等于量产工艺签核。[ASAP7 项目说明](https://github.com/The-OpenROAD-Project/asap7/blob/main/README.md)

全题目标为 **1000 ps（1 GHz）**、WC 角和种子 11/29/47。T06 的 `wr_clk`、`rd_clk` 也各按 1000 ps 约束，但两者是显式异步的独立时钟域；相同标称频率不改变其 CDC 性质。[PPA 基线清单](ppa-baselines.json)仅在十题均按本页参数完成验证后用于正式计分。本机使用 Yosys 0.69+150、OpenROAD 26Q2-1164-g08f67ee5ec 和仓库内 ASAP7。正式榜单还须锁定统一物理参数、工具镜像 digest、复核不同 RTL 写法的公平性并完成发布门禁。

## 全题统一的参数与例外

所有题目使用同一个 [ASAP7 平台修订](sources.lock.yaml)、工艺库组合、映射脚本、ABC 策略、时钟目标 `T_common=1000 ps`、I/O 延迟比例、驱动单元、输出负载、布局利用率、放置密度、布线层范围、RC 提取规则和三个固定布线种子。`config.mk`/SDC 由评测器生成，参赛者不得改动。**允许随题目变化的只有端口名、位宽、时钟个数和异步 CDC 例外路径的对象集合；数值参数不按候选或任务调优。** T01 用 `T_common` 约束输入到输出路径；T06 的 `wr_clk`、`rd_clk` 各为 1000 ps，但仅切除真正的跨异步时钟域路径，保留两域内部及同步器后级时序。

| 参数族 | 1 GHz 目标及待校准项 |
| --- | --- |
| 单元库 | ASAP7 7.5T、RVT、NLDM；WC/SS 时序，TT 活动功耗 |
| 映射与负载 | 固定 ORFS ASAP7 配置的 Yosys/ABC、`BUFx2_ASAP7_75t_R` 驱动与 3.898 fF 输出负载 |
| 全局时钟目标 | 所有任务及每个时钟域均为 1000 ps（1 GHz）；T06 的 `wr_clk`、`rd_clk` 虽同频但独立并声明为异步 |
| I/O 与物理约束 | I/O 延迟比例 20%；目标利用率与放置密度须十题统一探索并冻结 |
| 存储映射 | T03/T06/T08 的小型存储体和 T09 寄存器文件一律映射为标准单元，不使用 fake SRAM/寄存器文件 macro |
| 布线重复 | 固定种子 11/29/47；传给当前兼容版本的 ORFS `GRT_SEED` 和 `OR_SEED`，放置保持确定性，同一设计三次布线，指标取中位数 |

上述值来自九题实测，不是直接照搬 [ORFS 的 ASAP7 平台配置](https://github.com/The-OpenROAD-Project/OpenROAD-flow-scripts/blob/master/flow/platforms/asap7/config.mk)及[示例 SDC](https://github.com/The-OpenROAD-Project/OpenROAD-flow-scripts/blob/master/flow/designs/asap7/ibex/constraint.sdc)。

### 参数探索与冻结门禁

1. 先在 T01、T05、T09 的独立参考实现上做小规模矩阵试跑，筛去综合失败、布线失败、时序覆盖不足或成本超过评测机资源上限的组合；随后让候选**同一组合**跑完十题参考实现和每题至少一个功能等价的不同 RTL 写法；T10 在参考 RTL 完成后纳入。不针对某个任务单独放宽周期或更换映射策略。
2. 选择规则事先固定：全部参考设计完成合法映射和详细布线、全部受约束路径有端点、参考设计在共同 **1000 ps** 下 `report_worst_slack≥0`（T06 对两域分别检查，并切除跨异步域路径）、功耗活动注释达标、三种子 PPA 波动可控；如果物理参数有多个合格组合，优先选重复性更好、流程运行成本更低者。当前 OpenROAD 与锁定 ORFS 的 `global_placement -random_seed` 不兼容，因此只对全局和详细布线传种子；这三次重复不等于三次独立放置。保留所有失败组合与选择理由。
3. 冻结工具镜像 digest、Yosys/OpenROAD/ABC 精确版本、ASAP7 文件 hash、完整 `config.mk`/SDC、库角、ABC 脚本与 `-D` 目标、输出负载、物理及 RC 参数、三个种子、参考三元组和 PPA 排名分档宽度。冻结后所有参赛提交以及参考设计都从头用这套配置重跑；不能根据某个系统的表现再调参。
4. 十题中任一参考设计在 16 vCPU/32 GiB 限额下无法运行，或需要专用宏才可布线时，先修正**全套统一参数或任务规模**并重新校准；不得让部分题用另一套工艺配置。参数探索和评测器隐藏运行不计入参赛者完成任务的时间。

## 统一物理测量

1. 固定的 ORFS/ASAP7 流程使用 Yosys 映射，OpenROAD 完成放置、时钟树、详细布线，OpenRCX 依据锁定规则抽取 RC。小型存储统一映射为标准单元。生成的单元网表须通过短功能回归；若失败，先核查工具与模型，再判定候选设计的综合语义问题。
2. 三个固定布局种子各运行一次；每次记录标准单元面积 `A`、SS 角最坏受约束路径延迟 `D` 和 TT 角能耗 `E`，各指标取三次中位数。`A` 包括寄存器、逻辑、插入的缓冲器与时钟单元，排除填充单元、测试平台和封装。全部时钟域都要满足 `WNS≥0`；组合题输入到输出须满足共同 `T_common`。T06 的 `D` 为两域各自最坏路径的较大值。
3. 在固定工作负载上运行**对应种子的布线后网表**门级仿真，把 VCD/SAIF 切换活动与布线 RC 导入 OpenROAD，在 TT 角由其 `report_power` 报告泄漏、内部与切换功耗。换算 `E = P_avg × 窗口时长 / N_ops`，同时公开 `P_avg` 及各分量。活动注释率至少 95%；不足时先修评测流程，不能用缺失活动的低功耗结果排名。
4. 对可复现的候选 RTL 原因（不能合法映射或布线、违反共同周期、真实活动缺失）记 PPA=0；工具基础设施失败则用同一配置重跑，不处罚候选者。保存综合、布局、布线、RC、STA、功耗和功能回归的原始日志。即使有布线 RC，所得指标仍是 ASAP7 公开预测工艺上的**相对估计**。

## 固定功耗工作负载

功耗运行使用隐藏但在赛前固定的种子与事务分布；输入不得含规范外行为，且每个设计完成同样数量的**有用操作**。工作负载中的所有响应仍由独立模型检查，不能只测活动。基准实现同样运行。各题有用操作定义如下：

| 任务 | 有用操作与活动覆盖 |
| --- | --- |
| T01 | 一次输入向量变化；包含零、单热、多热和翻转较多的向量 |
| T02 | 一次输入 bit 的上升沿采样；平衡 0/1 与不同连续游程 |
| T03 | 一次成功读出且对应先前成功写入；复位丢弃的未读写入不计有效操作，空/满与中等占用混合 |
| T04 | 一次完成的 APB 访问；计时器在固定负载中的倒计数活动计入该访问序列的总能耗 |
| T05 | 一次成功输出；固定竞争强度与背压分布 |
| T06 | 一次成功读出且对应先前成功写入；功能负载覆盖多个非锁相频率比，冻结 PPA/功耗负载固定 `wr_clk=1.0 GHz`、`rd_clk=1.0 GHz` 且两域独立持续运行 |
| T07 | 一次完成的 AXI 读或写；固定读写、等待、错误和背压比例 |
| T08 | 一次完成的 CPU 请求；固定读写、命中、干净/脏缺失比例 |
| T09 | 一条正常退休指令；固定整数、分支、load/store 比例和数据端等待分布 |
| T10 | 一个完成的 16×16 输出块；十种模式、正常活动值、独立 A/B scale 与随机正负；必须在持续输入/四槽输出稳态窗口测量，计入多块并行与背压恢复能耗。负载的种子、块数与门级验证结果在冻结 PPA 基线时一同发布 |

`N_ops` 由评测方在门级测试平台的端口握手、采样事件或 CPU 退休事件中自动计数；固定负载的活动比例避免通过选择容易的操作降低能耗。对停顿较长的实现，窗口时长增大，因此能耗/操作会反映吞吐损失。初始复位、加载程序和测试平台初始化不计入功耗窗口；负载内的运行中复位及重启开销按同一规则计入所有候选。

## PPA 分数和时间的关系

每题预先冻结一个由独立参考实现测得的正数三元组 `(A_ref,D_ref,E_ref)`。参考实现必须功能全通过、满足周期约束且代码经同行评审，防止以臃肿基线虚增分数。对于候选的正数 `(A,D,E)`：

```text
S_PPA = clamp(14 × clip(A_ref/A,0.5,2)^0.35
                 × clip(D_ref/D,0.5,2)^0.35
                 × clip(E_ref/E,0.5,2)^0.30, 0, 20)
```

参考实现得到 14/20 分；相较参考实现的优化可升至 20。面积、延迟和能耗的比值分别裁剪到 `[0.5, 2.0]` 再代入，以免单项极端值支配评分。未满足目标周期、无法合法布线或无有效功耗活动的**候选原因**导致 PPA=0；工具原因导致无有效分数，应修正后对全部提交重跑。

排名用[PPA 分档](methodology.md#分层评分与排名)处理测量精度，目标分辨率为 `q=0.5` 分；同档才以完成时间排序。冻结前须在目标配置上评估跨种子、跨机器和跨工具镜像的重复性，并同时公开分档边界及原始 PPA 分数。若候选最终提前完成，但未全功能通过，时间仍被记录却不获时间分。完成时间分采用[统一规则](methodology.md#分层评分与排名)的 `5 × (1 − t/T_max)`，仅用作排序的最后一层。

## 防止 PPA 游戏化

- 不允许候选读取功耗种子或针对测试名/固定 PC 做特化；所有 PPA 工作负载仍验证功能。
- 不允许通过改变接口时序、引入违反题卡的额外流水级或延后响应降低功耗；相应功能/性能门禁先判定。
- 禁止参赛者提交自己的 SDC、Liberty、物理约束或替换映射单元；只提交 RTL 和验证交付物。
- 保存三次布局的原始报告、功耗注释率、工作负载 hash 与抽取脚本输出，便于审计。
