# T10：多精度脉动阵列验收计划

本计划细化[题卡](tasks.md#t10--多精度-44-脉动阵列矩阵乘法)和[验收组](acceptance.md#t10--多精度脉动阵列矩阵乘法)。目前属于**待实现的隐藏验收计划**；公开的 20 例端口冒烟和[数值 oracle](../evaluator/matmul_oracle.py)已实现，不能据此声称正式验收完成。

## 独立数值判定

评测方从固定端口驱动每条合法命令，保存握手时刻的 `mode/A/B/scale`，用整数和 `fractions.Fraction` 解码、乘法及点积。整数模式比较 16 个 signed INT64 精确值；浮点模式对 16 个 binary32 元素逐个比较题卡误差界、NaN/∞类别和高 32 位。参考模型不读取 PE、累加器、有效位、Agent 自带 `results.json` 或测试环境。每个失败记录 task、group、seed、命令序号、模式、矩阵行列、输入数据 hash、预期类/值/界限、实际 64-bit 输出、握手及响应周期；若有最小化器，仍保存原始向量供重放。

| 组 | 最低隐藏规模与必须覆盖的点 |
| --- | --- |
| MM-INT | 每种整数模式至少 64 条命令，其中 16 条定向（零、单元素、最高地址元素、±1、最大/最小值、交替符号）；其余固定种子随机。至少一条使结果绝对值超过 signed 32-bit 范围，核对 64-bit 符号扩展 |
| MM-F16 | FP16/BF16 各至少 64 条有限命令；±0、最小/最大次正规、最小 normal、±1、相邻指数、强抵消、不同矩阵行列组合；随机生成先精确计算再过滤为有限点积且无中途 binary32 溢出 |
| MM-F8 | E4M3/E5M2 各至少 64 条有限命令；E4M3 `0x7e=448`、`0x01=2^-9`，E5M2 `0x7b=57344`、`0x01=2^-16`，正负两种符号；重点防止把 E4M3 exponent 全一误判为全部特殊值 |
| MM-F4 | 至少 64 条命令；16 种 nibble 编码逐一出现，含 +6、−6、±0.5；每行/列覆盖 k=0、31、32、63，验证整个 1024-bit 总线和 nibble 位序 |
| MM-MX8 | E4M3/E5M2 各至少 64 条有限命令；各行/列 scale 独立，scale 0、126、127、128、254，验证 `2^(s−127)`；第二个 scale 字节置随机噪声且不应影响 K=32 的结果 |
| MM-MX4 | 至少 96 条命令；同一行/列两个 block 采用不同 scale；专门在 k=31/32 两侧放非零元素，再测 k=63 和最高总线位；包含两个 block 贡献相反并部分抵消的向量 |
| MM-PROTO | 至少 80 条混合模式命令，随机输入/响应背压 0–30 拍；握手后下一拍改写全部输入；运行中在计算、响应等待各异步复位至少 8 次；复位后不得出现旧响应 |
| MM-SYSTOLIC | 十种模式各至少 8 条无响应背压命令，在命令握手边沿计时，首个 `rsp_valid` 不超过 K+12；单独审查每个 PE 的水平/垂直邻接寄存、局部累加和波前有效位，不以延时测试代替结构证明 |
| MM-CORNER | 每种支持特殊值的模式至少 16 条命令：NaN（含 MX scale=255）、单向∞、0×∞、正负∞相消；BF16/FP16/FP8 次正规及舍入边界；任一浮点输出高 32 位须零 |

随机有限向量采用按模式分层的元素编码与尺度分布，覆盖符号、指数、零、稀疏、密集及抵消；每组至少 3 个固定种子。每条命令都比较全部 16 个输出，除专门的部分分组外，不能只抽查对角线。无效 `mode=10..15` 不驱动。测试平台给每条命令 `K+12` 延时上界加有限握手等待上界，失败立即记录可重放的最短上下文。

## 结构、PPA 与发布门禁

结构检查分两层：自动提取 elaborated RTL 的 16 个等效 PE 累加状态、A 水平/B 垂直寄存路径及 wavefront 有效位；两名评测工程师根据同一 RTL SHA-256 复核不规则编码、资源边界及串行冒充。结构得分必须有可审计证据，不由实例名称或注释单独决定。

至少 12 个有效变异体分别触发位序、符号、FP8 E4M3 特殊编码、E5M2 特殊编码、FP4 次正规、MX scale 指数、scale=255、block 边界、PE 水平/垂直链、漏累加、响应背压、运行中复位和串行计算延时错误。参考 RTL 全组通过、每个变异体的违规点被至少一条对应组用例检出后才能锁定隐藏分数。

统一 2500 ps WC、ASAP7、Yosys/OpenROAD 和三个布线种子必须用于 T10 参考实现；工作负载按完成的 4×4 输出块计能耗，十种模式比例和输入活动分布赛前固定。如果 16 vCPU/32 GiB 内无法布线、时序不满足或功耗注释不足，调整**全套统一参数或在保持两条 1024-bit 总线及全部格式要求前提下重审 T10 微架构/题目规模，并重新校准**；不得给 T10 单独加宽周期或虚构基线。正式榜单要等本项、隐藏验收、变异校准和交付门禁全部完成。
