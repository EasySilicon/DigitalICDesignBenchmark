# T10：持续双 1024-bit/拍脉动阵列验收计划

本计划细化[题卡](tasks/T10/task.md)和[验收组](tasks/T10/acceptance.md)。T10 采用持续流接口：精确格式和数值规则以[公开 oracle](tasks/T10/public/matmul_oracle.py)及题卡为准。公开材料包含数值 oracle 和端口冒烟样例；正式评分所需的独立参考、自动验收、缺陷变异体与物理 PPA 基线必须一同冻结。

输入模式限于 INT8/INT16、FP16/BF16、FP8、FP4、MXFP8、MXFP4，不包含 FP32 或 INT32 输入。输出仍按题卡使用 binary32 或 INT64 编码。

## 带宽与端口模型

每个输入握手传输 A/B 各 1024 bit。块首拍 `in_start=1`，同拍采样 16-bit 块 ID、mode 和两个 256-bit scale；其余 `w−1` 个有效拍依次传送 k 方向数据，`in_start=0`。一旦首拍被接受，DUT 必须为该块余下的每个时钟保持 `in_ready=1`；发送方暂停 `in_valid` 时计数不变。无输出背压的长流中，首拍间隔严格为前一块的 `w`，块间无气泡。随机混合流按前一块模式计算下一首拍时间。

延时上限以最后一个输入拍为起点：首行 64 拍、末行 80 拍。允许计算归约与输出汇集加寄存级；评测仍逐拍检查持续吞吐与输出行槽占用。

输出最多每拍 4 个独立的 1024-bit 行槽，各带块 ID 和行号，槽号递增定义同拍顺序。`out_ready` 一次接收当拍所有有效槽；背压时有效槽元数据和数据保持不变。每块输出 0..15 行恰好各一次、按行号递增；不同块可以交织。无背压时每块首行在最后输入拍后 ≤64 拍、末行 ≤80 拍。运行中复位丢弃所有在途块，复位释放后不得出现先前在途块的 ID。

**有限缓冲与背压**：无限输出停顿下不要求无限输入吞吐。DUT 可在块边界撤回 `in_ready`，但已接受块的余下输入拍不得被阻塞，输出不得丢失或重复。测试包含最长 32 拍的连续输出背压、行组和列均有不同结果的矩阵、连续 FP4/MXFP4 满速块与输出背压重叠，以及满速长流中撤回、释放 `out_ready` 的恢复过程；在 `out_ready=1` 且无积压的正式吞吐窗口内不得以背压例外放宽速率。

## 必跑的自动验收组

| 组 | 隐藏刺激与检查 |
| --- | --- |
| MM-INT | INT8/INT16 各至少 64 块；零、单点、高位、±1、最大/最小值、交替符号和随机满密度；256 个 signed INT64 精确相等 |
| MM-F16 | FP16/BF16 各至少 64 块；±0、最小/最大次正规、最小 normal、相邻指数、抵消，以及从完整 16-bit 编码空间采样的随机矩阵 |
| MM-F8 | E4M3/E5M2 各至少 64 块；最高值、最小次正规、正负号、特殊值编码，以及从完整 8-bit 编码空间采样的随机矩阵 |
| MM-F4 | 至少 64 块；全部 16 种 nibble，k=0/31/32/63 与最高输入位参与结果；随机矩阵覆盖全部合法编码 |
| MM-MX8 | E4M3/E5M2 各至少 64 块；元素从完整 8-bit 编码空间采样；scale 0/126/127/128/254/255、独立行列配置、跨 k=31/32；定向检查超出 binary32 的正负项抵消后最终为 1，以及有限/无穷边界 |
| MM-MX4 | 至少 96 块；元素覆盖全部 16 种编码；两个 scale block、最高 nibble、极值抵消与有限/无穷边界 |
| MM-PROTO | 首拍与块 ID、输入暂停、输出背压、元数据仅首拍有效、相邻格式切换、运行中复位；每块全部 256 个数值结果仍须正确 |
| MM-SYSTOLIC | 16×16 PE 自动网表检查；如下持续吞吐、四槽输出、块内不停顿、逐块延时和混合流；每块全部 256 个数值结果仍须正确 |
| MM-CORNER | NaN、真∞、0×∞、正负∞相消、MX scale=255、真负∞与溢出的正有限部分和、舍入边界和高 32 位零 |

| 持续流 | 无背压输入/输出窗口 | 必须自动检查的稳态输出 |
| --- | --- | --- |
| ST-4 | FP4 与 MXFP4 各至少 256 块，各块首拍严格相隔 4 拍 | 首块首拍后第 64 拍至最后输入拍，每拍 `popcount(out_valid)=4`，且 `in_ready=1` |
| ST-8 | INT8、两种 FP8、两种 MXFP8 各至少 64 块，各块首拍相隔 8 拍 | 对应窗口每拍 `popcount(out_valid)=2`，且 `in_ready=1` |
| ST-16 | INT16、FP16、BF16 各至少 64 块，各块首拍相隔 16 拍 | 对应窗口每拍 `popcount(out_valid)=1`，且 `in_ready=1` |
| ST-MIX | 至少 512 块固定种子混合模式，包含 4→16、16→4、MX scale 切换 | 相邻首拍间隔等于前块 `w`；所有行按 ID 归属且无丢失、重复、串块 |
| ST-BP/RST | 128 块 INT8/MXFP4 混合流中周期性连续 32 拍输出背压；部分块内由发送方插入一拍 `in_valid=0`，非首拍故意改变 ID、mode、scale；另在块内、波前及待输出时分别复位 | 背压期间有效槽稳定；块间可等信用、块内 `in_ready` 始终为 1；仅首拍元数据生效；已接受块完整结束或被复位整体丢弃；恢复后不死锁 |

稳态窗口从首拍被采样的上升沿计起，第 64 个后续上升沿开始，持续至最后输入拍的上升沿。禁止把先缓存整块、等全部输出后才接受下一块的设计计为持续吞吐通过。每个失败记录组、种子、块 ID、模式、输入拍/输出周期、行列坐标、预期/实际值与端口握手；每块比较全部 256 个结果，数值错误使该块不通过。

## 结构、物理与发布

Yosys 网表自动检查 256 个同型 PE、两组正交 16×16 寄存邻接链、局部累加反馈、所有 lane 对结果的影响、所有 PE 结果对输出的贡献，以及非 PE 状态位数 ≤262,144。结构规则不读取信号名或人工评审意见。性能以端口周期判定；网表正确而不能持续收/发的设计不得 MM-SYSTOLIC 分。至少 12 个有效缺陷变异体应覆盖“单块突发通过但块间插气泡”“四槽输出不足”“块 ID 串扰”“满队列后丢行”等错误。

正式 PPA 目标使用与其他任务相同的 Yosys/ASAP7/OpenROAD、**1000 ps / 1 GHz** WC 和种子 11/29/47。功耗负载必须覆盖持续流的稳态。功能、吞吐、交付和物理条件均通过后才建立独立参考三元组；逐提交评分全自动。更多发布条件见[任务验收计划](tasks/T10/acceptance.md)和[统一发布门禁](README.md#发布门禁)。

当前冻结功能参考的 SHA-256 为 `248faca64fba735b879cad919f1f57a3cd638a7c784c6c35c8a223cd81538f91`：2,752/2,752 块、704,512 个输出点、复位探针、256-PE 网表结构和 14/14 个有效缺陷变异体均已通过。200 块持续功耗负载的 51,200 个输出点也已由公开 oracle 独立核对。现有同哈希 1 GHz 物理结果只覆盖局部结果存储子块，不能作为完整 16×16 顶层的三种子 PPA 参考；在 seeds 11/29/47 的完整顶层布线、寄生时序和活动功耗冻结前，T10 只报告功能试评分，PPA 与时间记为未启用。
