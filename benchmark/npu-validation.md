# T10：双 1024-bit/拍脉动阵列验收计划

本计划细化[题卡](tasks.md)和[验收组](acceptance.md)。公开端口冒烟及[数值 oracle](../evaluator/matmul_oracle.py)可运行。私有验收驱动现已生成 960 块、逐元素比较全部 256 个输出，并用协议桩完成全量驱动试跑；独立参考 RTL、变异体、结构双人复核及三种子 PPA 基线**尚未完成**，所以 T10 仍不得正式计分。

## 数据流与独立模型

评测方在命令握手时锁定 mode 和两条 256-bit scale；后续每个输入握手同时捕获两条 1024-bit A/B 数据拍。对于 w=16/8/4，各命令必须分别接收 16/8/4 拍，每拍 16 个行向量与 16 个列向量，单向量分别含 4/8/16 元素。输入 `in_valid` 连续时 `in_ready` 不得撤回；暂停 `in_valid` 后拍号不前进。评测方以整数与 `fractions.Fraction` 精确解码和点积，检查按序输出的全部 16 行、256 个 C 元素。行为 oracle 不读内部 PE、Agent 的测试环境或 `results.json`。

| 组 | 最低隐藏规模与边界 |
| --- | --- |
| MM-INT | INT8/INT16 各至少 64 块；零、单点、高位、±1、最大/最小值、交替符号与随机满密度；至少一项超过 signed 32-bit 范围 |
| MM-F16 | FP16/BF16 各至少 64 块；±0、最小/最大次正规、最小 normal、相邻指数、抵消和随机矩阵 |
| MM-F8 | E4M3/E5M2 各至少 64 块；E4M3 `0x7e=448`、`0x01=2^-9`，E5M2 `0x7b=57344`、`0x01=2^-16`，含负号 |
| MM-F4 | 至少 64 块，全部 16 种 nibble 编码；每个输入拍的最高位、k=0/31/32/63 都出现非零项 |
| MM-MX8 | E4M3/E5M2 各至少 64 块；scale 0/126/127/128/254，行列独立配置，k=31/32 两组不同 scale |
| MM-MX4 | 至少 96 块；k=31/32 两侧非零且异 scale，k=63 与最高 nibble 非零，包含跨组部分抵消 |
| MM-PROTO | 至少 80 块混合模式；输入暂停、输出背压 0–30 拍，输入握手后改写数据；计算中与输出等待中各至少 8 次异步复位 |
| MM-SYSTOLIC | 十种模式各至少 8 块连续输入；逐拍确认双 1024-bit 握手，最后输入拍后 48 拍内首行有效，零背压时 16 行连续输出；另审查邻接寄存与 PE lane 并行度 |
| MM-CORNER | 各支持特殊值的模式至少 16 块；NaN、单向∞、0×∞、正负∞相消、MX scale=255、舍入边界和输出高位 |

随机有限向量按符号、指数、零、稀疏和抵消分层，每组至少三个固定种子。失败日志记录组、种子、命令号、模式、输入拍与矩阵坐标、预期值/误差界、实际 64-bit 结果及握手周期。每块比较全部 256 个输出，不能只抽查对角线。无效 mode 不驱动。

当前私有试运行的分组规模依次为 `MM-INT=128`、`MM-F16=128`、`MM-F8=128`、`MM-F4=64`、`MM-MX8=128`、`MM-MX4=96`、`MM-PROTO=80`、`MM-SYSTOLIC=80`、`MM-CORNER=128`，共 960 块；随机用例从三个固定种子交错生成。评分按[score_rules.json](../evaluator/score_rules.json)固定：六个功能组各 10 分，协议、脉动、边界组三组各 5 分。各组全通过得满分，通过率至少 50% 得半分，低于 50% 得零分；`MM-SYSTOLIC` 是关键组，任何失败均使该组得零分。仅在 F+P=75/75 且交付合格时按[统一 PPA 公式](ppa.md#ppa-分数和时间的关系)比较参考三元组，之后才有完成时间分。未经参考实现、变异体和三种子基线验证的私有试运行只能产生诊断分，不能冒充正式成绩。

所有块的数值输出都由 oracle 记录并检查；`MM-PROTO` 的 5 分只按握手、背压、复位和行协议判定，`MM-SYSTOLIC` 的 5 分只按逐拍带宽、延时、连续行及结构证据判定，避免同一个数值错误在功能组和协议组重复扣分。

## 结构、PPA 与发布

静态审查应追踪 256 个逻辑 PE 的局部 C 累加、A 右传/B 下传的寄存路径、波前有效位及 FP16/8/4 对应的 4/8/16 lane 并行。至少两名工程师按候选 RTL SHA-256 复核工具无法识别的等价编码；实例名或注释不作为合格证据。变异体至少 12 个，覆盖位序、符号、格式特殊值、MX scale、block 边界、PE 链、lane 串行化、输入气泡、输出背压及复位。

参考 RTL 必须全组通过，变异体均有对应检出证据。T10 使用与 T01–T09 完全相同的 2500 ps WC、Yosys/ASAP7/OpenROAD 参数和三种子路由。门级工作负载按完成的 16×16 输出块计能耗，十种模式比例赛前固定。若无法在 16 vCPU/32 GiB 限额下布线或满足时序，应重新审查微架构及全套统一参数，不得给 T10 单独放宽周期或虚构基线。
